# 灵犀智能客服系统 - 后端接口文档
## 版本：v3.0 | 前端对接专用

---

# 基础信息

## 请求地址
开发环境：http://localhost:8000
生产环境：http://{your-domain}

## 统一响应格式
{
  "code": 200,
  "message": "success",
  "data": {},
  "page_info": {
    "total": 100,
    "page": 1,
    "page_size": 20,
    "total_pages": 5
  }
}

## 认证方式
所有需要登录的接口，Header 携带：
Authorization: Bearer {access_token}

用户 Token：localStorage.getItem('token')
管理员 Token：localStorage.getItem('admin_token')

## Token 有效期
access_token：2小时
refresh_token：7天（存 Redis，支持主动失效）

# 一、用户认证接口 /api/v1/auth

## 1.1 用户注册
POST /api/v1/auth/register（白名单，不带Token）

请求体：
{ "username": "zhangsan", "password": "Password123",
  "nickname": "张三", "phone": "13800138000" }

## 1.2 用户登录
POST /api/v1/auth/login（白名单，不带Token）

响应：
{
  "code": 200,
  "data": {
    "access_token": "eyJ...",
    "refresh_token": "eyJ...",
    "token_type": "bearer",
    "expires_in": 7200
  }
}

## 1.3 获取当前用户信息
GET /api/v1/auth/me（需要用户Token）

## 1.4 更新用户信息
PUT /api/v1/auth/me（需要用户Token）

## 1.5 修改密码
PUT /api/v1/auth/me/password（需要用户Token）

## 1.6 刷新 Access Token
POST /api/v1/auth/refresh（不带Token）

请求体：{ "refresh_token": "eyJ..." }
响应：{ "data": { "access_token": "eyJ...", "expires_in": 7200 } }

## 1.7 退出登录
POST /api/v1/auth/logout（需要用户Token）

# 五、对话接口 /api/v1/chat

## 5.1 WebSocket 连接
WS /api/v1/chat/ws/{channel_token}?user_id={uid}

固定 channel_token：LrDSr5ZRFjCu0mBunFxOTiMTTVeZ8m7xCJhqygIfHmw

注意：
- user_id 必须是整数，不能传字符串 "guest_xxx"
- 用户未登录时不传 user_id，后端自动降级为匿名模式
- 直接连接后端 8000 端口，不走 Vite 代理

## 5.2 前端发送消息格式
{ "type": "chat",     "content": "我要退款" }
{ "type": "transfer", "content": "我要转人工" }
{ "type": "ping" }

## 5.3 后端推送消息格式

普通消息：
{
  "type": "message",
  "role": "bot",           // bot / agent / system
  "content": "回复内容",
  "message_id": 6,
  "conversation_id": 2,
  "agent_name": null,
  "timestamp": "2026-05-13 18:02:02",
  "extra": {
    "intent": "order_query",
    "emotion": "neutral",
    "answer_source": "tool",
    "card_type": "order",
    "card_data": { ... }
  }
}

转人工通知：
{
  "type": "transfer",
  "role": "system",
  "content": "已为您转接人工客服 小美，请继续描述您的问题",
  "agent_name": "小美",
  "timestamp": "..."
}

思考中：{ "type": "thinking", "content": "正在思考中..." }
错误：  { "type": "error",    "content": "处理消息失败" }
心跳：  { "type": "pong" }

## 5.4 sender_type 枚举（messages 表）
0 → User（用户）
1 → Bot
2 → 人工客服（Agent）
3 → System（系统消息）

## 5.5 answer_source 来源说明
rag / keyword / tool / llm / default

## 5.6 intent 意图类型
order_query / logistics_query / refund_request /
product_query / complaint / greeting / other

## 5.7 提交评价
POST /api/v1/chat/conversations/{id}/evaluate（需要用户Token）

请求体：{ "rating": 5, "tags": ["回复及时"], "remark": "非常满意" }

## 5.8 获取会话列表（管理员）
GET /api/v1/chat/conversations（需要管理员Token）

查询参数：page / page_size / status / start_date / end_date

## 5.9 获取消息记录（管理员）
GET /api/v1/chat/conversations/{id}/messages（需要管理员Token）

# 六、知识库管理接口 /api/v1/knowledge

## 6.1 获取知识库列表
GET /api/v1/knowledge/bases（需要管理员Token）

## 6.2 创建知识库
POST /api/v1/knowledge/bases（需要管理员Token）

请求体：{ "name": "电商通用知识库", "description": "覆盖退款/物流/订单场景" }

## 6.3 获取知识条目列表
GET /api/v1/knowledge/bases/{id}/items（需要管理员Token）

查询参数：page / page_size / keyword / category

## 6.4 Excel 批量导入
POST /api/v1/knowledge/bases/{id}/import（需要管理员Token）
Content-Type: multipart/form-data

Excel 列格式：
A列：知识ID（有则更新，无则新增）
B列：类目
C列：知识标题（标准问题）
D列：相似问法（多个换行分隔）
E列：答案类型（text/html）
F列：答案内容
G列：标签（逗号分隔）

响应：{ "data": { "task_id": "import_xxx", "total": 100 } }

## 6.5 查询导入进度
GET /api/v1/knowledge/import/progress/{task_id}（需要管理员Token）

响应：
{
  "data": {
    "task_id": "import_xxx",
    "status": "running",       // pending/running/success/failed
    "status_text": "导入中",
    "total": 100,
    "success": 45,
    "failed": 2,
    "current": 47,
    "message": "已处理 47/100"
  }
}

## 6.6 知识库检索测试
POST /api/v1/knowledge/bases/{id}/search（需要管理员Token）

请求体：{ "query": "我要退款怎么操作", "top_k": 5, "threshold": 0.85 }

## 6.7 更新知识条目
PUT /api/v1/knowledge/items/{id}（需要管理员Token）

## 6.8 删除知识条目

# 十一、数据标注接口 /api/v1/annotations

## 11.1 创建/覆盖标注（UPSERT）
POST /api/v1/annotations（需要管理员Token）

请求体：
{
  "conversation_id": 1,
  "message_id":      6,
  "label":           "bad",
  "correct_answer":  "您可以在订单页面点击申请退款，选择退款原因后提交即可。",
  "remark":          "原答案不够详细"
}

## 15.1 接入代码

<script
  src="https://your-domain.com/widget.js"
  data-channel="LrDSr5ZRFjCu0mBunFxOTiMTTVeZ8m7xCJhqygIfHmw"
  data-user-id="123"
  data-user-name="张三"
  data-color="#5b8af5"

</script>

## 15.2 字段说明

必填：
data-channel     渠道唯一标识（从后台渠道管理页获取）

强烈建议：

data-user-name   当前登录用户昵称

可选：
data-color       主题色（默认 #5b8af5）
data-position    按钮位置 right/left（默认 right）
data-text        按钮文字（默认「联系客服」）

# 十六、前端对接注意事项（完整版）

## 16.1 request.js Token 隔离规则
管理员接口前缀（使用 admin_token）：
├── /api/v1/admin/
├── /api/v1/reports/
├── /api/v1/knowledge/
├── /api/v1/bots/
├── /api/v1/agents/
├── /api/v1/channels/
└── /api/v1/annotations/

用户接口（使用 token）：
├── /api/v1/orders
├── /api/v1/auth/me
└── /api/v1/chat/（WebSocket 除外）

白名单（不带Token）：
├── /api/v1/auth/login
├── /api/v1/auth/register
├── /api/v1/admin/auth/login
├── /api/v1/admin/auth/me
├── /api/v1/products（公开商品）
└── /api/v1/channels/{id}/config/public

## 16.2 sender_type 枚举（messages 表）
0 → User（用户）
1 → Bot
2 → 人工客服（Agent）
3 → System（系统消息）

## 16.3 管理员 role 枚举
0 → super_admin（超级管理员）
1 → admin（管理员）
2 → operator（运营人员）
3 → viewer（只读用户）

## 16.4 订单状态枚举
0 → 待付款
1 → 已付款
2 → 已发货
3 → 已完成
4 → 已取消
5 → 退款中
6 → 已退款

## 16.5 intent 意图类型
order_query       → 订单查询
logistics_query   → 物流查询
refund_request    → 退款申请
product_query     → 商品咨询
complaint         → 投诉
greeting          → 打招呼
other             → 其他

## 16.6 answer_source 来源
rag      → 知识库检索
keyword  → 关键词干预
tool     → 工具调用
llm      → 大模型生成
default  → 兜底回复

## 16.7 卡片类型与组件对应
card_type      组件                  状态
order          OrderCard.vue         ✅ 已完成
order_list     OrderListCard.vue     ✅ 已完成
logistics      LogisticsCard.vue     ✅ 已完成
product        ProductCard.vue       ✅ 已完成

## 16.8 分页参数规范
请求：{ page: 1, page_size: 20 }
响应：{ total, page, page_size, total_pages }

## 16.9 错误码说明
200 → 成功
400 → 参数错误
401 → 未登录或Token过期
403 → 无权限
404 → 资源不存在
422 → 参数验证失败
500 → 服务器内部错误

401处理规则：
├── 管理员接口401 → 清除admin_token → 跳转 /admin/login
└── 用户接口401   → 清除token      → 跳转 /login
两端互不影响！

# 七、核心业务设计

## 7.1 对话流程
用户发送消息
    ↓
第一层：Bot（FAQ知识库拦截）
├── 关键词干预（最高优先级）
├── BM25（0.3）+ Embedding（0.7）混合检索
└── 相似度阈值：0.85（可配置）
    ↓ 匹配不上
第二层：Agent（LangGraph）
├── 意图识别（7种意图）
├── 情绪检测（neutral/negative/angry）
├── RAG 检索
├── 工具调用（订单/物流/退款/商品）
├── 生成回答
└── 置信度判断
    ↓ 兜底
转人工（AI模拟人工客服 + LLM生成接待语）

## 7.2 人工状态管理
- 超过1分钟无消息 → Celery 自动重置为智能客服模式
- 每次打开对话窗口 → 前端强制重置 isTransferred=false
- 历史消息从后端拉取完整显示
- 人工状态不跨会话保留

## 7.3 渠道接入方式
独立页面：/chat?channel={token}&user_id={uid}
iframe嵌入：<iframe src="..." />
JS挂件：<script src="widget.js" data-channel="..." data-user-id="..." />

## 7.4 渠道内容配置
- 热点问题（猜您想问）：最多8条，支持拖拽排序，换一批
- 活动Banner：最多5个，横版大图，支持跳转链接
- 快捷标签：最多10个，底部入口，支持emoji图标

# 八、已知问题与注意事项

## 8.1 已解决问题
- bcrypt密码长度限制 → 改用 sha256_crypt
- messages.role → 改为 sender_type（smallint）
- conversations 无 closed_at → 用 updated_at 估算时长
- Bot/Agent Token 冲突 → 按URL前缀严格隔离
- user_id 类型问题 → 统一转为 int
- RAG节点异常未rollback → 加 await db.rollback()
- 人工状态跨会话残留 → 每次打开强制重置
